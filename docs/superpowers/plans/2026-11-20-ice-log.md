# Ice Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Invited friends (and the owner) log on-the-ice reports with an A+ … F- grade, a
photo and a note; anyone can leave moderated public comments; reports feed the daily ice
model; the owner moderates on a review page with almost no phone notifications.

**Architecture:** A free Cloudflare Worker (`worker/`) with D1 (reports, comments,
invites, devices, prefs) and Workers KV (resized photos) sits between the static map and
storage; it holds every secret. The browser resizes photos and reads their GPS before
upload. The daily GitHub Actions job pulls reports, prefs and the pending count from the
Worker with a service token, checks photo/device GPS against lake outlines (Python already
has them), and applies grades in the model.

**Deviation from the spec (planning finding):** `lakes.geojson` is 11.7 MB and Workers
Free allows ~10 ms CPU per request, so the Worker cannot check GPS against lake outlines or
process images. GPS checking moves to the daily job, and photos are resized and stripped
in the browser before upload. Consequence: no originals are ever stored (better for
privacy and the 1 GB KV limit); pending photos are kept 21 days, then deleted unless
featured.

**Tech Stack:** Cloudflare Workers (ES modules JS), D1, Workers KV, Turnstile, cron
triggers, `wrangler` + `vitest` with `@cloudflare/vitest-pool-workers` (dev only);
existing Python 3.12 daily job; existing vanilla-JS map; `exifr` in the browser.

**Spec:** `docs/superpowers/specs/2026-11-20-ice-log-design.md`

## Global Constraints

- Free, no-card Cloudflare only: Workers Free, D1, Workers KV, Turnstile, cron triggers. No R2, no Images, no paid add-ons. Owner rule: default to the free option at every opportunity.
- Workers Free CPU budget is ~10 ms per request: no parsing of `lakes.geojson`, no image processing in the Worker.
- Repo is public: never commit display names, reporter ids, notes, coordinates, photos, device keys, tokens or ntfy topics. Friends' reports live in D1 only.
- Secrets never reach a browser except the user's own device key. Never log secrets or ntfy topic names.
- Notifications: no push per comment/photo/report. One line in the morning alert when it goes out anyway; at most one ntfy reminder a week, only if an item has waited more than 7 days.
- Grades: `A+ A A- B+ B B- C+ C C- D+ D D- F+ F F-`. Every grade means skateable. A+ … C- = good skating (may alert); D+ … F- = skateable but rough (no alert, grade shown). Grade allowed only with `skated` or `rough`.
- Comments: plain text, no links, ≤ 500 characters; strangers held for approval; invited friends publish immediately; comments never change labels.
- Featured photos: metadata-free, ≤ 1600 px long side, at most 6 per lake, newest first, owner-approved.
- Invites work once, on one device. Revoke cuts access only.
- Owner's reports are always trusted; friends' reports with GPS more than 300 m from the chosen lake are `unverified` and ignored by the model; reports without GPS are used and flagged.
- Product name in UI copy: "Ice Log"; add button: "Log the ice".

## Review Focus

1. **Phone resends a queued report after a flaky connection** → saved once (idempotency key), not twice. Test in Task 2.
2. **Photo picked on iPhone/Android with location stripped** → report still sends; offer "Use my location"; reaches the model flagged `no_gps`. Tests in Tasks 2 and 6.
3. **Stranger pastes a link or 2,000 characters, or posts 10 comments in a minute** → rejected with a clear message; 4th comment within an hour from the same device/IP is refused. Test in Task 3.
4. **Revoked friend's phone keeps trying** → 401, the page drops its key and shows "This invite was switched off"; their queued items are discarded, not retried forever. Tests in Tasks 1 and 6.
5. **Worker down at daily-run time** → daily job logs, pings nothing extra, and runs on repo data as before (weather + imagery + owner's old repo reports). Test in Task 5.

## D1 schema (Task 1 creates; later tasks rely on these names)

```sql
CREATE TABLE friends (id TEXT PRIMARY KEY, name TEXT NOT NULL, role TEXT NOT NULL CHECK (role IN ('owner','friend')), revoked_at TEXT, created_at TEXT NOT NULL);
CREATE TABLE invites (code_hash TEXT PRIMARY KEY, friend_id TEXT, role TEXT NOT NULL, name TEXT, created_at TEXT NOT NULL, used_at TEXT);
CREATE TABLE devices (key_hash TEXT PRIMARY KEY, friend_id TEXT NOT NULL REFERENCES friends(id), created_at TEXT NOT NULL);
CREATE TABLE reports (id TEXT PRIMARY KEY, idem_key TEXT UNIQUE NOT NULL, friend_id TEXT NOT NULL, lake_id TEXT NOT NULL, day TEXT NOT NULL, created_at TEXT NOT NULL, rating TEXT NOT NULL, grade TEXT, note TEXT NOT NULL DEFAULT '', lat REAL, lon REAL, gps_source TEXT CHECK (gps_source IN ('photo','device')), photo_id TEXT);
CREATE TABLE photos (id TEXT PRIMARY KEY, public_id TEXT UNIQUE NOT NULL, lake_id TEXT NOT NULL, friend_id TEXT NOT NULL, created_at TEXT NOT NULL, status TEXT NOT NULL CHECK (status IN ('pending','featured','rejected')), decided_at TEXT);
CREATE TABLE comments (id TEXT PRIMARY KEY, lake_id TEXT NOT NULL, name TEXT NOT NULL, text TEXT NOT NULL, friend_id TEXT, sender_hash TEXT NOT NULL, created_at TEXT NOT NULL, status TEXT NOT NULL CHECK (status IN ('pending','published','rejected')));
CREATE TABLE prefs (id INTEGER PRIMARY KEY AUTOINCREMENT, lake_id TEXT NOT NULL, action TEXT NOT NULL CHECK (action IN ('pin','unpin','hide','unhide')), created_at TEXT NOT NULL);
```

Keys, codes and sender identifiers are stored only as SHA-256 hex (`hash()` in `auth.js`).
KV keys: `photo:<public_id>` → JPEG bytes. Meta key `meta:last_reminder` → ISO time.

## HTTP API (all JSON unless noted; `Authorization: Bearer <device key>` where marked)

| Method & path | Who | Body / result |
|---|---|---|
| `POST /api/bootstrap` | `Bearer <BOOTSTRAP_TOKEN>` secret; only while no owner exists | `{name}` → `{invite_url}` (owner invite) |
| `POST /api/invites/redeem` | anyone with a code | `{code, name?}` → `{device_key, name, role}`; 410 if used or friend revoked |
| `GET /api/me` | device | `{name, role}`; 401 if revoked/unknown |
| `POST /api/reports` | device | `{idem_key, lake_id, day?, rating, grade?, note?, gps?:{lat,lon,source}, photo?:<base64 jpeg>}` → `{id}` (200 on repeat idem_key, same id) |
| `GET /api/lakes/:lake_id` | anyone | `{comments:[{name,text,created_at}], photos:[{public_id,credit,created_at}]}` (published/featured only) |
| `GET /api/photos/:public_id` | anyone if featured; owner always | `image/jpeg` |
| `POST /api/comments` | anyone; device optional | `{lake_id, name, text, turnstile_token}` → `{status:"published"|"pending"}` |
| `GET /api/review` | owner | `{comments:[…pending], photos:[…pending], friends:[…]}` |
| `POST /api/review/comments/:id` `POST /api/review/photos/:id` | owner | `{action:"approve"|"reject"}` / `{action:"feature"|"reject"}` |
| `POST /api/invites` | owner | `{name?}` → `{invite_url}` |
| `POST /api/friends/:id/revoke` | owner | → `{ok:true}` |
| `POST /api/prefs` | owner | `{lake_id, action}` → `{ok:true}` |
| `GET /api/export?since=YYYY-MM-DD` | `Bearer <SERVICE_TOKEN>` secret | `{reports:[…], prefs:[…], pending:{comments, photos}}` |
